# Importing and exporting data

## Documents

Each document's **Export** tab gives its JSON. The **Import** button on every
collection's overview (Components, Sources, Hit Efficiencies, Activation)
adds documents from a file to the current version. The file can be:

- one JSON document, as exported;
- a JSON list of documents;
- a `.tar`, `.tar.gz` or `.zip` archive of such JSON files.

The JSON is MongoDB Extended JSON, so values like `{"$oid": "..."}` work.

Every imported document becomes a new item, with new ids:

- references between documents in the same file are linked to the new copies;
- references to documents that aren't in the version are dropped, and listed
  after the import;
- documents that fail to validate are reported, and the others are still
  imported.

To copy one item from another version *keeping* its identity, so that the two
versions can still be compared and merged, use the item's diff page instead;
see [Versions](versions.html#importing-a-single-document).

### Hit efficiencies

Hit efficiencies are usually imported this way, generated by a script from
your simulation output. A minimal hit efficiency looks like:

```json
{
  "source": "U238",
  "location": "CuCan",
  "material": "copper",
  "nprimaries": 1000000,
  "scalars": {
    "countrate": {"value": 2.3e-5, "sigma": 1e-6, "units": "1/Bq/g/s"},
    "countrate_above_2MeV": {"value": 0, "sigma": 0, "sigmaup": 2e-8, "units": "1/Bq/g/s"}
  }
}
```

A quantity is an object with `value`, `sigma` (the lower uncertainty),
optionally `sigmaup` (the upper, if different) and `units`. An upper limit has
value and `sigma` 0. A string in the [usual notation](model.html#entering-values),
e.g. `"2.3e-5 +- 1e-6 1/Bq/g/s"`, also works. Spectra are histograms in the
JSON spectrum format below, keyed by name, under `"spectra"`.

{: .note }
The JSON that the Export tab produces is the authoritative example of the
format for each collection.

## Spectra

Spectra are added to a hit efficiency on its **edit** page, under
**Spectra**: **Import spectrum**, **Rename** and **Delete**. These changes are
saved immediately.

Import takes a file and:

- **name**: defaults to the file name;
- **units** of the values, e.g. `dru/mBq`;
- **bins unit**, e.g. `keV`;
- **Replace an existing spectrum with the same name**.

Two file formats are accepted:

**Columns** (`.csv`, `.txt`, `.dat`): one row per bin,

```
# low high value [sigma [sigma_up]]
0    10   1.2e-3  1e-4
10   20   1.1e-3  1e-4
```

with 3 to 5 columns separated by commas or whitespace. Blank lines, `#`
comments and one header line are skipped. Bins must be contiguous and
increasing. With a fifth column the errors are asymmetric (`sigma` below,
`sigma_up` above).

**JSON**: an object with `bins` (the edges, one more than the values),
`value`, and optionally `sigma`, `sigmaup`, `units` and `binsunit`. Units in
the file take precedence over those in the form.

## Assays from radiopurity.org

**Import from radiopurity.org** on the Sources overview searches
[radiopurity.org](https://radiopurity.org) and imports the chosen records as
assays. See [Building a model](model.html#importing-from-radiopurityorg).

## Whole versions

A whole version can be exported to a `.bgx.tar.gz` file and imported again,
on this or another server. See [Versions](versions.html#export-and-import).
